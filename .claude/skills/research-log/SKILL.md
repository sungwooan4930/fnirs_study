# 연구 진행 로그 기록

`run_logging.md`는 이 과제의 **연구 노트**다. 1년 뒤 논문·특허·보고서를 쓸 때
"왜 그렇게 했는지"의 유일한 근거가 된다. 커밋 메시지로 대체할 수 없다.

## 기록 시점

- 기능 구현 완료 / 마일스톤 종료
- **설계 결정** — 특히 대안을 검토하고 하나를 고른 경우
- **실험 실행** — 모델 학습·평가를 1회 돌릴 때마다
- 계획서 스펙의 해석을 확정하거나 미확정 항목을 해소한 경우
- 실패·폐기 — **성공만큼 중요하다. 반드시 남긴다.**

## 형식

기존 파일의 날짜 역순 구조를 유지하고 아래를 이어붙인다.

```markdown
## YYYY-MM-DD — 제목

### 완료
- (구체적으로. "구현함" 대신 "무엇을 어떤 방식으로")

### 결정 사항
| 항목 | 결정 | 근거 | 대안 (기각 사유) |
|------|------|------|-----------------|

### 계획서 연계
목표 N (§계획서 항목) — 진척 / 미달 / 해석 변경

### 미해결
- [ ] (다음 세션이 이어받을 수 있게)
```

## 실험 기록 시 추가 필수 항목

모델 학습·평가를 기록할 때는 아래를 **빠짐없이** 적는다. 하나라도 빠지면 재현 불가능한 기록이다.

| 항목 | 예시 |
|------|------|
| 결과 디렉토리 | `results/2026-09-01_attn-fusion_seed42/` |
| git commit | `a1b2c3d` |
| config 스냅샷 | `config/model_attn.yaml` (해당 커밋 기준) |
| 시드 | `42` (numpy/random/torch 전부) |
| 데이터 범위 | `sub-01 ~ sub-30`, 제외: `sub-07`(SCI 불량) |
| **CV 방식** | `LOSO-CV` / `within-subject 5-fold` — **반드시 명시** |
| **chance level** | `33.3%` (3수준) |
| 성능 | `평균 ± std`, **최악 피험자 성능**, 혼동행렬 |
| 비교 기준 | 행동 단일 모달 대비 ΔAccuracy |
| 누수 점검 | `leakage-check` 실행 여부·결과 |

## 금지

- ❌ 성능 수치를 CV 방식·chance level 없이 기록
- ❌ 실패한 실험을 누락 (선택적 보고는 연구 부정의 시작이다)
- ❌ "잘 됨", "개선됨" 같은 정성 표현만 남기기 — 수치를 적는다
- ❌ 계획서와 다르게 구현한 사실을 기록하지 않고 넘어가기

## 작업 순서

1. `run_logging.md`를 읽어 최신 날짜와 구조를 확인한다.
2. 위 형식으로 항목을 작성한다.
3. 계획서(`docs/plan/연구계획서_텍스트추출.txt`)의 어느 목표에 해당하는지 연결한다.
4. `CLAUDE.md` §9 미확정 사항이 해소되었으면 **그 파일도 함께 갱신**한다.
