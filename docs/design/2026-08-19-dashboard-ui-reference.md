## 2. 채택할 미감

- **무채색/저채도 기반** (01, 02, 06) — 색을 신호 전용으로 남길 수 있다. HbO/HbR 발산 컬러맵
  (청↔백↔적), 위험 구간, 임계 초과 차원이 장식과 경쟁하지 않는다. 연구용 대시보드에서 이건
  미감이 아니라 판독성 문제다.
- **랩 리포트 프레이밍** (02) — `FIG. 2A / SESSION 402` 같은 그림 번호·캡션. 교수자가 근거를
  인용하고 논문에 옮기기 쉬워진다.
- **leader line 지표 목록** (02) — 6차원을 좁은 폭에 나란히 놓기 좋다.
- **이상치만 착색** (06) — 91.0%만 주황. 위험 구간 표시 규칙으로 그대로 쓸 수 있다.
- 헤어라인 보더, 큰 여백, small-caps 라벨, 소문자 대형 헤드라인.

## 3. ⚠ 정보 구조 — 교수자 뷰에는 그대로 쓸 수 없다

여섯 개 전부 **학습자 본인용 자기 모니터링**이다. §6의 결정으로 **학습자 뷰에는 직접 참고**가
되었지만, **교수자용 다인 모니터링 화면에는 아래 격차가 그대로 남는다.** 그리고 1차원 종합
점수와 근거 없는 판정어 문제는 **두 뷰 모두에 해당한다**(§6.4).

| 목업 공통 | 계획서 목표 4 |
|---|---|
| 단일 피험자 (`Subject 402`, `USER_ID 8829-X`) | 다수 학습자 동시 + 집단 분포 |
| 1~4개 지표 | **6차원 벡터** (인지부하·주의·피로·몰입·수행정확도·반응지연) |
| `optimal` / `High` — **판정만** | **판정 근거**: "전전두엽 HbO 23% 증가(기여도 0.41), α/θ 저하(0.28), 반응시간 증가(0.18)" |
| XAI 표면 없음 | **SHAP·어텐션 기여도가 화면의 중심** |
| 없음 | 교수전략 제안 + **수용 / 수정 / 거부** (자동 실행 금지) |
| 없음 | 위험 구간 자동 감지, **교수자가 임계치 조정** |

### 가장 위험한 지점

`01`의 `efficiency index 84.2%`, `05`의 `SYNC SCORE 92` 같은 **단일 종합 점수는 폐기된 4채널
집중도 측정기가 하던 바로 그것**이다. `CLAUDE.md` §10이 명시적으로 금지한다 — 1차원 집중도
지수를 6차원 벡터 대용으로 쓰지 말 것. 레이아웃을 그대로 옮기면 폐기한 자리로 되돌아간다.

`optimal`, `High` 같은 판정어도 같은 계열이다. 목표 4의 핵심은 **AI가 왜 그렇게 판단했는지를
교수자가 이해·검증·수정할 수 있게 하는 것**이므로, 근거 없는 판정어는 그 반대 방향이다.

## 6. 학습자 본인용 뷰 + 종단 프로필 (2026-08-19 사용자 결정)

**결정:** 교수자용 다인 뷰에 더해 **학습자 본인용 단일 피험자 뷰**를 추가한다. 학습자 프로필을
저장해 **반복 측정에 따른 변화**를 표현한다.

이로써 목업 6종의 단일 피험자 구조가 기각이 아니라 **학습자 뷰의 직접적 참고자료**가 된다.
`01`의 원형 게이지·푸터 통계, `04`의 세션 이력 리스트가 특히 그렇다.

### 6.1 계획서와의 관계 — 확장이다

| | 계획서 목표 4 | 이 결정 |
|---|---|---|
| 대상 | **교수자** ("교수자 지원", "교수자 친화적 최소 클릭 UI") | 교수자 **+ 학습자 본인** |
| 시간 범위 | 세션 내 실시간 ("학습자별 6차원 추이"는 교수자 화면 안) | **세션 간 종단** |
| 실험 설계 | 피험자 내, 카운터밸런스, 세션 1회 | 반복 측정 |

계획서에 없는 확장이므로 **임의 확정이 아니라 사용자 결정으로 기록**한다. 1년·2천만원 범위와
산출물(논문 3편·특허 3건)이 교수자 증강으로 프레이밍돼 있다는 점은 별도로 유효하다.

### 6.2 IRB와 현장 적용은 다른 층위다

**정정 (2026-08-19):** 초기 기록은 두 층위를 섞었다. 바로잡는다.

| 층위 | 관할 | 학습자 프로필 |
|---|---|---|
| **검증 실험** (30명) | **IRB** | 참가자에게 자기 프로필을 보인다면 그 사실을 프로토콜에 기재 |
| **현장 적용** | 개인정보 처리방침·기관 협의 | **학습자 본인과 교수자가 확인하는 것이 정상 기능** |

현장 적용 시스템에서 학습자가 자기 인지상태 프로필을 보는 것은 이 시스템의 목적이지 예외가
아니다. IRB는 연구 참가자 보호 장치이며, 배포된 교육 도구의 사용자 기능을 규율하지 않는다.

연구 리포지토리 규칙(`CLAUDE.md` §5.3)은 그대로다 — **식별정보는 어느 경우에도 커밋하지 않는다.**
운영 시스템의 신원 처리는 리포지토리 밖의 별개 관심사다.

### 6.3 세션 간 변동성 — 설계로 해결 (2026-08-19 반영)

세션 간 변화를 표시하려면 비교 가능성을 파이프라인이 보장해야 한다. **매 세션 베이스라인
측정을 프로토콜에 넣고, 세션별 독립 정규화를 전처리에 넣었다.**

→ `CLAUDE.md` §2.4 (세션 구조), §3.1 (전처리 체인), **§3.8 (정규화 규칙·표시 규칙·시뮬레이터 요구사항)**

핵심만:

- 세션 구조는 `베이스라인 → [과제 블록 × N] → 베이스라인`. 생략 불가.
- fNIRS mBLL의 기준 구간을 **그 세션의 시작 베이스라인**으로 고정. EEG 대역 파워는 베이스라인
  대비 비율/dB. 행동은 절대값 유지(장비 재부착 영향 없음).
- 정규화는 **세션 단위 독립**. 여러 세션을 모아 정규화하면 측정하려는 세션 간 차이가 지워진다.
- 표시할 때는 **동일 과제 조건 내에서만** 비교한다. 시작·종료 베이스라인이 크게 벌어진 세션은
  신뢰도 낮음으로 표시하되 **감추지 않는다**.
- 연습 효과는 정규화로 지워지지 않는다 — 과제 조건별로 분리해 보고 세션 번호를 공변량으로 남긴다.

**목표 3에 생긴 숙제:** 현재 합성 생성기는 단일 세션만 만든다. 위 대응이 실제로 작동하는지
보이려면 **세션 간 베이스라인 이동을 모사**해야 한다 — 정규화 전에는 세션 간 분류가 무너지고
정규화 후에는 회복되는 것을 테스트로 증명한다. 서브프로젝트 B에서 처리한다.

### 6.4 1차원 지표 함정이 여기서 다시 온다

"시간에 따른 변화"는 단일 점수를 쓰고 싶어지는 자리다. `01`의 `efficiency index 84.2%`가 정확히
그 형태다. 학습자 뷰에서도 **6차원을 유지**한다. 종합 점수를 쓰려면 그 정의와 가중치를 명시하고
근거를 함께 표시해야 하며, 그렇지 않으면 폐기한 4채널 집중도 측정기로 되돌아간다
(`CLAUDE.md` §10).

### 6.5 학습자 뷰에 매핑

| 목업 | 학습자 뷰에서의 쓸모 |
|---|---|
| `01` 푸터 3분할 (sessions / total time / streak) | 세션 수·누적 측정시간은 그대로 유효 |
| `01` 원형 게이지 | **6차원 레이더로 교체.** 이번 세션 vs 개인 기준선 오버레이 |
| `04` 최근 세션 리스트 | **그대로** — 세션 이력 진입점 |
| `02` leader line 지표 | 6차원 각각의 세션 간 변화량(Δ)을 나란히 |
| `06` 이상치만 착색 | 유의하게 변한 차원만 강조 |
| `03` `σ 2.4` | 개인 내 변동성 표기 참고 |

### 6.6 아직 결정하지 않은 것

- 학습자에게 **어느 차원까지** 보일지 (피로·인지부하는 민감할 수 있다)
- 추정 불확실성을 어떻게 표시할지 — 점추정만 보이면 과신을 부른다
- 프로필 저장 위치·보존 기간·삭제 요청 처리 (개인정보 처리방침 사안)
- 교수자 뷰와 학습자 뷰가 **같은 앱인지 분리된 앱인지**

## 7. 아직 결정하지 않은 것 (공통)

- **대시보드 스택** (`CLAUDE.md` §9.2-5): React+FastAPI(WebSocket) vs Streamlit/Dash. 미확정.
- 실시간성 요구 수준 — 계획서는 "실시간 시각화"라고만 명시. 갱신 주기 미정.
- 한 화면에 학습자 몇 명까지 표시할지.
- 6차원을 한 화면에 모두 보일지, 우선 차원만 보이고 나머지는 드릴다운할지.

이 문서는 위 결정들을 **하지 않는다.** 목표 4 착수 시 `superpowers:brainstorming`으로 연다.
